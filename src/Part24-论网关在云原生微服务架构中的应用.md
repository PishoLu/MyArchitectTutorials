## 摘要

2023 年 3 月份，我作为系统架构师，负责设计并开发了“AI 智能材料文献解析平台”，本文围绕一款面向材料行业的科研论文智能解析平台，重点阐述了 API 网关在系统微服务架构中的核心功能、技术实现与落地成效。该平台整合了 50 年来材料领域学术论文，通过 AI 技术实现文献解析、分类与交互式知识检索，涉及多子系统协同工作。作为系统流量的统一入口，API 网关承担了动态路由、安全认证、流量治理及可观测性数据收集等关键角色。实践表明，网关通过集成 SpringCloudGateway 与 Nacos 实现服务无感知扩缩容；借助 JWT 令牌与限流机制构建多层次安全防护；通过链路追踪与日志聚合显著提升系统可观测性与故障定位效率。网关的引入有效简化了客户端交互，隐藏内部服务细节，提升系统稳定性与开发效率，为后续智能运维与服务治理深化奠定了坚实基础。

## 正文

我就职于一家为材料行业提供数字化服务软件的公司，我司与多个钢厂、材料研究室、高校合作多年。近年来，为应对材料科研人员在文献调研、数据挖掘和科研思路获取方面的痛点，结合最新的 AI 技术发展迅猛的势头，我司决心给行业科研人员提供一便捷、智能化的科研论文智能解析平台，该平台不仅收容了过去 50 年内的材料行业相关论文，通过 AI 对论文进行解析、分类、提取关键词，同时也支持在线对用户上传的文件进行文字提取、AI 解析、AI 知识库交互。该项目由用户与学者管理、文献管理、文献 AI 解析、智能算法推荐等多个子系统组成，在历经 8 个月的设计开发后，在 2023 年底上线，至今运行与维护长达两年，得到了行业内各人士的一致好评。我作为系统架构设计师，负责了该系统的设计与研发。

网关作为所有外部流量进入内部微服务的唯一入口，其重要程度不言而喻，不仅仅是流量的路由器，更是微服务架构的“门面”和“守护神”。其核心功能和关键技术特性如下。

统一接入与动态路由：来来自客户端（Web、App、小程序）的所有 API 请求汇聚到单一端点，并根据预定义规则（如路径、请求头、权重）将请求动态路由到后端的相应微服务实例中。这就需要网关必须能和注册中心无缝集成，动态感知服务实例的上线与下线，实现真正的“无感知”服务扩容与迁移。我们使用了 SpringCloudGateway 通过与 Nacos 集成，实现了路由规则的自动更新。

认证授权与安全防护：作为系统流量的第一道关卡，网关是执行身份验证的理想场所，所有请求首先在网关进行 JWT 令牌校验、APIkey 验证等，避免了非法请求直接冲击内部微服务。网关可以进行粗粒度的授权，例如验证请求是否具有访问某个 API 分组的权限。细颗粒度的授权仍在业务服务内完成。这构成了纵深安全防御的第一层。

流量治理与容错：对入口流量进行精细化的控制和管理，并收集全量的访问日志、指标和追踪信息。包含限流与负载均衡：在可用的服务实例间分发请求，提高系统吞吐量和资源利用率，保护后端服务不被突发流量冲垮。熔断与降级：当某个后端服务响应缓慢或大量失败时，网关可以快速熔断对该服务的请求，将后续请求路由到其他的健康实例中，或者直接返回一个预设的降级响应，避免故障蔓延，保障核心业务链路的可用性。

可观测性数据收集：网关时所有流量的必经之路，是生成可观测性数据的“金矿“。包含指标收集：与 Prometheus 等监控系统集成，暴露如 QPS、响应时长、错误率等关键指标，为系统监控和告警提供数据支撑。链路追踪透传：将唯一的追踪 ID 注入请求头并透传给后端服务，与 Jaeger 等链路追踪系统联动，实现跨服务调用的全链路分析。Api 访问日志：记录所有经过网关的请求与响应信息，是审计和问题排查的第一手资料。

请求/响应转换与 Api 聚合：在将请求发送给后端服务前，可以添加、修改或删除头部信息，例如注入用户身份信息、设置内部服务间通信的认证令牌等，在收到服务响应后，可以对后端服务的响应进行修改，比如过滤敏感数据、统一响应格式、添加公共头部等，确保返回给客户的数据是规范和安全的。同时针对特定场景，客户端的一个请求可能需要多个微服务的数据，网关可以将这些请求聚合，向多个服务发起调用，并将返回结果组合后返回给客户端，减少网络往返次数，提升用户体验。

经过上述落地实践，API 网关在项目中发挥了不可替代的作用，取得了显著成效，简化了客户端，提升了安全性，客户端只需与网关一个端点交互，后端服务的任何拆分、合并、升级对前端透明。内部微服务网络拓扑得以隐藏，有效收敛的攻击面。架构解耦与治理能力下沉，将跨切面的治理逻辑从业务服务中剥离，统一在网关层面实现，使得业务团队可以更专注于领域逻辑开发，而运维和架构团队可以集中精力优化流量调度和系统稳定性，实现了高效的职责分离。通过限流和熔断机制，成功抵御了多次因爬虫或用户突发行为导致的流量激增，避免了系统雪崩，上线之初由于实际用户超过预测用户，网关的限流规则有效的保护了后端的 ElasticSearch 集群，保障了核心服务的可用性。可观测性数据的统一收集使得开发与运维团队有了后续改进与优化的数据支撑，一次我们通过 Grafana 观察，迅速发现调用推荐服务的 P99 延迟升高，通过 Jaeger 追踪链路，最终定位到是某个 Spark 离线特征更新任务拖慢了数据库，从而影响到了实时推荐服务。整个排查过程从过去的小时级缩短到分钟级。

API 网关的成功落地，完美的扮演了”交通枢纽“和”边防哨所“的角色，不仅是流量的入口，更是安全、治理和可观测性的基石。技术的探索永无止境，未来我们计划在网关层面进一步探索，基于 AIOps 通过机器学习算法实现异常检测和自动弹性伸缩预测，与 Istio 服务网关进行更明确的分工协作，共同构建更加稳固和智能的微服务网络基础设施。为科研事业提供更坚实的技术支撑。
